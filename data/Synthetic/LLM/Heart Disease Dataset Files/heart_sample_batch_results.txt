================================================================
DIFFICULTIES AND LIMITATIONS
================================================================

1. SMALL FEATURE SPACE → DUPLICATE COLLISIONS
Heart Disease has only 14 columns, most of which are binary or have
3-4 possible values. With this limited combinatorial space, randomly
generated rows collide frequently. Adult Income (15 cols including
fnlwgt with millions of unique values) and Credit Card Default
(24 cols with continuous bills/payments) had zero duplicates.
Heart Disease consistently produced 5-19 duplicates per 500-row batch.

This is itself a finding: LLM synthetic generation is harder for
datasets with small categorical feature spaces. There's a structural
limit on diversity that no prompt engineering can fully overcome.

2. MEMORIZATION RECURRENCE
The real Cleveland dataset is well-known and tiny (303 rows), so
Claude has seen it many times during training. When we provided 100
sample rows in the prompt, Claude periodically reverted to copying
those rows verbatim instead of generating new ones.

We had to discard 3 batches entirely:
  - One with 95 exact matches (~19%)
  - One with 87 exact matches (~17%)
  - One with 422 exact matches (~84%)

Starting fresh chats helped reset this behavior. Adding "Do NOT
reproduce any rows from the attached sample" to the prompt reduced
but did not eliminate the issue.

This is a real concern for using LLMs to generate synthetic data
from small, well-known datasets. The model's prior knowledge of the
dataset competes with the instruction to generate new data.

3. CLAUDE WROTE CODE INSTEAD OF CSV
Multiple times Claude tried to "solve" the generation task by writing
Python scripts to sample from distributions instead of just outputting
CSV rows directly. We had to explicitly add "Do NOT write code or
scripts. Output the synthetic data directly as CSV rows" to the prompt.

This appears to be a behavior where the LLM treats the task as a
programming problem rather than a generation problem. The scripts it
wrote were also worse than direct generation, they produced more
duplicates and less natural variation.

4. STRUCTURAL DISTRIBUTION GAPS
Without distribution constraints, some categories were systematically
underrepresented. Final batch had 0% cp=1 (real has ~7.6%). Earlier
batches frequently overrepresented thal=6 (rare in real data ~6%,
sometimes 9-11% in synthetic).

5. ROW MERGE ISSUES
At one point during batch generation, two rows got concatenated on a
single line with no newline between them, causing the validation
script to fail with a parser error. Required manual inspection and
correction. This is a fragility of relying on LLM-generated text
output rather than structured data formats.

6. TIME COST
Heart Disease generation took several hours of active work, much
longer than Adult Income or Credit Card Default. The combination of
duplicates, memorization, and Claude attempting to write scripts
meant many batches had to be discarded and regenerated.

Tradeoff observed:
  Constrained prompt → cleaner output, no memorization, no duplicates
  Sample rows prompt → memorization risk, duplicate collisions, but
  arguably more "natural" because Claude is learning patterns from
  examples instead of explicit frequency targets

Heart Disease was the hardest of the three datasets to generate
without distribution constraints. The combination of small feature
space, well-known dataset (high memorization risk), and limited
training data made unconstrained generation particularly challenging.
